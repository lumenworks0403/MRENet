## 3. 关键语义（来自源码）

- **数量**：M = batch 内单图最多目标数，G = max(100 // M, 1)，Ndn = 2·M·G。
- **组内布局**：每组长度为 2M，前 M 位是正样本区，后 M 位是负样本区。第 b 张图在每个区里只占前 n_b 位，其余位置是 padding（内容为 0，参考框经 sigmoid 后是 (0.5,0.5,0.5,0.5)）。
- **序列顺序**：`[DN | 普通查询]`。
- **mask（True 表示看不见）**：普通查询的行对所有 DN 的列都是 True；每个 DN 组的行，对本组以外的 DN 列是 True；DN 可以看到普通查询。
  - 这个 mask 只用于 decoder 的 self-attention。文本的 key padding 仍然通过 `text_attention_mask` 传给 text cross-attention，两者分开处理。
- **τ 的含义**：每个并行分支独立地以概率 τ 重新调用生成器，得到新的噪声、新的 mask 和新的 meta；否则继承共享层的完整输出（包括 DN 部分和普通部分），并沿用 mask₀。
  - τ=0 表示全部继承，DN 仍然存在，并不等于关闭 DN。
  - τ=1 表示全部重新生成。
- **只重新初始化 DN 查询**：任何 decoder 层的参数都不会被重置。
- **监督**：
  - 正样本 DN 的分类目标是该描述的 positive token map，同时计算 L1 和 GIoU。
  - 负样本 DN 和 padding 位的分类目标全为 0，不计算框损失。官方 `label_weights` 全为 1，所以 padding 位也计入分类损失。
  - 分类损失和框损失都除以 batch 内正样本 DN 的总数（至少为 1）。官方 `bg_cls_weight=0`。
- **重新生成的 DN 与 DN₀ 布局相同**：同一个 batch 的 GT 不变，所以两者的数量和索引布局完全一样。代码里每层仍然保存自己的 meta（`layer_meta[i]`），并用断言检查这一点。
- **各层 DN 损失如何合并**：论文正文写的是对各分支取平均；官方代码是逐层相加（`d{i}.dn_loss_*`）。这里按代码实现。

## 4. 文本指代任务的适配（方案 A，属于本项目适配）

- 一条描述视为一个类别，所有 GT 的 label 都是 0，`label_book_size=1`。
  - 官方微调时的类别数是数据集类别数；B0 没有类别编号。
  - 因此 25% 的类别替换总是换回 0，类别噪声实际上不起作用。这是如实迁移的结果。
- **DN 标签嵌入**：使用新建的 `dn_generator.label_embedding`，shape 为 (1, 256)，按 `nn.Embedding` 默认的 N(0,1) 初始化，与官方相同（DINO 的 `init_weights` 不会覆盖它）。
- **DN 分类监督**：用 `build_positive_map` 给出的该描述正 token。一条描述对应多个目标时，这些目标共用同一组正 token。
- **没有目标的描述**：该图只有 padding 位，分类目标全为 0，不产生框损失。整个 batch 都没有目标时不生成 DN，并按官方做法加一项 `label_embedding·0`。
- **预训练权重中的 `label_enc.weight`**：IDEA 原版的 DN 标签表。B0 构建的 groundingdino 不含这个模块，它一直被当作 unexpected key 忽略（原 B0 也是如此）。它的行号对应预训练数据的类别编号，与“一条描述 = 类别 0”的语义对不上，所以不加载。shape 未核实（需要在服务器上打印）。
- **没有采用句子向量**：官方源码里找不到依据。

## 5. 数据流（训练且 use_dn=True）

```
GT boxes ──CdnQueryGenerator──> DN₀ (label_query, bbox_unsig, mask₀, meta₀)
第0层  输入 [DN₀ | tgt]，参考框 sigmoid([DN₀框 | refpoint])，self-attn mask₀
       → shared_out, shared_ref（喂给下一层的参考框做 detach，预测头用的不 detach）
分支 m (1..5)：rand < τ ?
   是：输入 [DNm | shared_out 普通部分]，参考框 [sigmoid(DNm框) | shared_ref 普通部分]，maskm，metam
   否：输入 shared_out（完整），参考框 shared_ref（完整），mask₀，meta₀
预测头：第 i 层框 = bbox_embed_i(hs_i) + inverse_sigmoid(head_refs_i)
       head_refs 的普通部分，第0层是初始框，第1~5层都是共享层的更新框（同 no-DN 版的修复）
拆分：前 Ndn 个 → dn_outputs（6 层 logits/框 + layer_meta）
      其余 → 普通查询：掩码、Hungarian 匹配、aux 损失、推理汇总
```

- 推理、DN 关闭、或整个 batch 都没有目标时，走原来的 `hed_parallel_decode`，代码路径与 no-DN 版相同。
- 普通查询的初始化、数量、顺序和 top-k 选择都在 DN 插入之前完成，不受 DN 影响。
- 普通查询之所以与 no-DN 版逐元素相同，是因为 mask 让普通查询看不到 DN，而其余算子都是逐查询独立计算的。

## 6. 与官方代码不同的地方

1. **重新生成分支的 DN 参考框**：官方 `pre_decoder` 存的是 inverse_sigmoid 值，decoder 第 435 行直接把它和 [0,1] 坐标拼接，没有做 sigmoid。这样参考框会落在 logit 值域。
   - 默认 `branch_ref_mode="sigmoid"`，与共享层 DN 的处理方式一致。
   - `"official_raw"` 选项可以逐字照搬官方，用于对照。
2. **官方 head 的参考框配对**：官方 head 用 `references[i]` 配第 i 层，这是串行结构的假设。这里沿用 no-DN 版的修复，每层用自己实际消费的参考框。
3. **GIoU 坐标系**：这里在归一化坐标上算，与 B0 普通查询的损失一致；官方在像素坐标上算。
4. **抽签次数**：官方抽 6 次签只用前 5 次；这里只抽 5 次。
5. **不做跨卡平均**：单卡训练，不做 `reduce_mean`。

## 7. 掩码适配边界

- 不新增 DN 掩码损失，因为论文是检测任务，没有这一项。
- DN 只算分类和框，不进入 MaskHead、Hungarian 匹配、六层汇总，也不进入最终的目标选择。
- 拆分发生在掩码计算之前，不会为 DN 生成全分辨率掩码。
- 简单说：DN 部分是“检测式 DN”，掩码仍然是原有的普通查询分割监督。

## 8. 配置与 checkpoint

- **新开关**：`use_dn`，默认 False；`dn=dict(...)`，默认值见 `rrs/model_mode.py::DN_DEFAULTS`，可用 `--opts dn.reinit_rate=0.25` 这样的方式覆盖。
- **三种模式**：
  - B0：`use_hed=False`
  - HED-structure/no-DN：`use_hed=True, use_dn=False`
  - HED+DN：`use_hed=True, use_dn=True`
  - `use_hed=False, use_dn=True` 会报错。
- **use_dn=False 时完全不创建 DN 模块**：不消耗随机数，state_dict 与原来相同。DN 模块在 FPN/MaskHead 之后创建，所以即使打开 DN，FPN/MaskHead 的初始化也与原来相同。
- **checkpoint 中的配置**：`cfg` 会保存 `use_dn` 和 `dn`，`resolve_model_mode` 负责恢复。老 checkpoint 没有 `use_dn`，按 False 处理。
- **加载规则**（`model.py::load_model_state`，替代原来的 `strict=True`）：
  - 允许缺失的键只有 `dn_generator.label_embedding.weight`，对应把 B0 或 HED-no-DN 的 checkpoint 加载进 HED+DN 模型的情况。
  - 把 HED+DN 的权重加载进 DN 关闭的模型时，会显式丢弃 `dn_generator.*`（推理不用它们）。
  - 其余任何缺失或多余的键都会报错。
- **已知限制**：从 no-DN 的 checkpoint 打开 DN 并继续训练（`--resume` 且不加 `--eval-only`）时，优化器多了一个参数组成员，`optimizer.load_state_dict` 会报错。按照“不修改恢复训练逻辑”的约束，这里没有处理。如果要这样做，应改用该权重做初始化，重新开始训练。
- **配置文件**：`configs/b0_hed_dn_rislad.py` 和 `configs/b0_hed_dn_refcoco.py`。
  - 关闭 DN、恢复 no-DN：加 `--opts use_dn=False`，或直接用原来的 `b0_hed_*.py`。

## 9. 测试（服务器上运行）

```bash
python tests/test_hed.py               # 原 no-DN 测试（未修改）
python tests/test_mode_entrypoints.py  # 模式/入口，已新增 DN 用例
python tests/test_dn.py                # DN 生成、mask、分支、损失（CPU）
python tools/smoke_dn.py --config configs/b0_hed_dn_rislad.py --iters 2   # 真实模型，最多 2 个 batch
```

- `smoke_dn.py`：不保存权重、不写日志、不调用 `optimizer.step`。它会检查以下几项，并输出 JSON，最后一项 `PASS` 汇总结果：
  - DN 数量与 metadata 一致；
  - 损失和梯度有限，且共享层、分支、label_embedding 的梯度非零；
  - eval 不需要 targets；
  - 同一份权重在 DN 开、关两种模型上的 eval 输出一致；
  - checkpoint 往返后模式和参数正确恢复。
