- 论文：SegMAN（CVPR 2025），MMSCopE 见第 3.3 节与图 3(d)。

官方代码里**没有** `class MMSCopE`。按调用链定位，MMSCopE 实际是
`SegMANDecoder.forward_winssm` 里"降采样 → Pixel Unshuffle → 通道压缩 → 拼接 → 单次 SS2D 扫描
→ 1×1 混合 → 上采样投影"这一整条路径，扫描模块是 `VSSMBlock(token_mixer=VSSM)`，
`VSSM` 就是 SS2D。

### 层级名对应（务必注意 `c4` 的歧义）

官方 `c4` 指**最深层**（1/32）；**本工程 `c4` 指 1/4 浅层特征**。按分辨率映射：

| 官方 | 分辨率 | 本工程 |
|---|---|---|
| `F2` / `c2` | 1/8 | `enc_maps[0]` |
| `F3` / `c3` | 1/16 | `enc_maps[1]` |
| `F4` / `c4` | 1/32 | `enc_maps[2]` |
| `c1`（官方 MMSCopE 不用） | 1/4 | 与本工程 `c4` **不是同一个东西** |

代码里把官方的 `linear_c4/c3/c2` 改名成 `linear_c32/c16/c8`，就是为了消除这个歧义。

### 框架包装替换的逐项说明（适配 A2）

官方 `ConvModule(norm_cfg=dict(type='SyncBN'), act_cfg=dict(type='ReLU'))` →
`rrs/mmscope_pixel_decoder.py::conv_norm_act`：

| 项目 | 官方 | 本工程 | 是否一致 |
|---|---|---|---|
| 顺序 | `conv → norm → act`（ConvModule 默认 `order`） | 同 | ✅ |
| conv bias | `bias='auto'` → 有 norm 时 `False` | `bias=False` | ✅ |
| 激活 | `ReLU(inplace=True)` | 同 | ✅ |
| conv 初始化 | ConvModule 默认 `kaiming_init(mode='fan_out', nonlinearity='relu')` | `nn.init.kaiming_normal_(fan_out, relu)` | ✅（mmcv 默认用 normal 分布） |
| norm 初始化 | `constant_init(1, bias=0)` | `weight=1, bias=0` | ✅ |
| 归一化类型 | SyncBN | **默认 GroupNorm(32)**，`mm.norm="bn"` 可切回 | ❌ 已改，理由见下 |

**为什么默认不用 BN**：本工程 `batch_size=1~2` 单卡，而官方 `image_pool` 先
`AdaptiveAvgPool2d(1)` 再过 ConvModule——BatchNorm2d 在 `batch=1` 的 `1×1` 特征上训练时
直接抛 `Expected more than 1 value per channel`。GroupNorm 与现有 `FPNPixelDecoder`
已经在用的 `GroupNorm(32, dim)` 约定一致。改动只限于新支路，没有碰模型任何其他归一化。

### 其他与原算法的差异（逐条）

| 编号 | 差异 | 原因 | 影响 |
|---|---|---|---|
| A1 | 官方在 1/8 直接接分类头；本工程把上下文特征上采样到 `c4` 实际尺寸，与 1/4 浅层做 `1×1 lateral + 相加 + 3×3 Conv/GN/ReLU + 1×1 out` | 需要 1/4 的 `pix` 且通道匹配现有 MaskHead；复用现有 FPN 末段写法，不新增注意力/门控 | **本项目接口适配**，不是官方设计 |
| A2 | ConvModule → `conv_norm_act`，SyncBN → GroupNorm(32) | 见上 | 归一化统计口径与官方不同 |
| A3 | 仅在新模块内部把 1/8 特征 replicate-pad 到 4 的倍数，算完裁回 | `pixel_unshuffle(4)` 与 stride-4 conv 要求能整除；800×1333 的 1/8 约 100×167（167 % 4 = 3） | 不改变对外尺寸与坐标恢复语义 |
| A4 | SS2D 调用处关闭 autocast 并转 FP32（`mm.scan_fp32=True`，默认） | `selective_scan_cuda_oflex` 要求 `u/delta/B/C` dtype 相同，而 AMP 下 LayerNorm 产 fp32、conv1d 产 fp16；官方只在 FP32 下训练 | 只这一处转 FP32（扫描在 1/32 分辨率），其余卷积仍按外部 AMP；**不**把整个模型改 FP32 |
| A5 | 不加载任何 SegMAN 预训练权重 | 通道宽度与 Swin/GroundingDINO 不匹配，加载无意义 | 新支路全部随机初始化 |
| A6 | 不按 `_no_weight_decay`（`A_logs` / `Ds` 带该标记）排除 weight decay | 本轮约束"不新增微调策略"，`build_optimizer` 的分组逻辑保持原样 | 与官方 MMSeg 配置不同，已记录为未对齐项 |

### 内部通道宽度的选择依据

| 参数 | 默认 | 依据 |
|---|---|---|
| `mm.channels` | 128 | 官方 `segman_t_ade.py` 的 `channels=128`（最小档）。本工程输入 800×1333，1/8 特征约 100×167 ≈ 16.7k 位置，是 ADE20K 512×512 下 64×64 = 4k 的约 4 倍，取最小档控制计算量。SS2D 扫描通道 = `3*channels` = 384 |
| `mm.feat_proj_dim` | 256 | 与 GroundingDINO `hidden_dim=256` 相同，逐层投影不扩张也不压缩 |
| `mm.gn_groups` | 32 | 与现有 FPN 的 `GroupNorm(32, dim)` 一致；128/256/384/512 都能整除 |
| SS2D `d_state` | 1（不开放配置） | 官方 `VSSMBlock` 不向 `token_mixer` 传 `d_state`，固定走 `VSSM` 默认值 1 |

这些值**没有调参**，也**不对应任何官方权重**。

### 真实算子要求

`third_party/SegMAN/segman/mmscope_core.py::require_scan_ops()` 在构造 `VSSM` 时检查
`selective_scan_cuda_oflex`、`triton`、`einops`、`timm`，缺任何一项抛 `ImportError`
并打印安装命令。**没有任何替代实现**：不用卷积、池化、注意力或 Identity 冒充 selective scan，
`output/model_skeleton.py` 里的 `SS2DFallback` 没有被使用。
`use_mmscope=False` 时 `rrs/model.py` 根本不 import 这些模块（`import` 写在 `if use_mmscope:`
分支里），旧 B0/HED 在没有这些依赖的环境中照常运行。

## 2. MMSCopE 像素支路的数据流与形状

接口与原 FPN 完全一致：`pix = self.pixel_decoder(c4, enc_maps)`，`_forward_b0` 与 `_forward_hed`
的调用处一字未改。

```text
enc_maps[0] (B,256,H8,W8)  ─ StageProj ─┐
enc_maps[1] (B,256,H16,W16) ─ StageProj ─┤ 双线性上采样到 (H8,W8)
enc_maps[2] (B,256,H32,W32) ─ StageProj ─┘
                      concat(3*256) ─ linear_fuse(1x1,GN,ReLU) ─> F  (B,128,H8,W8)
F ─ short_path(1x1) ──────────────────────────────────────────┐
F ─ image_pool(AdaptiveAvgPool2d(1) + 1x1) ─ 上采样 ───────────┤
F ─[pad 到 4 的倍数]─┬─ pixel_unshuffle(4) ─ reduce_channels[2] ─┐
                    ├─ conv_downsample_2(3x3,s2) ─ unshuffle(2) ─ reduce_channels[1] ─┤ concat
                    └─ conv_downsample_4(5x5,s4) ───────────────  reduce_channels[0] ─┘  (B,384,H32',W32')
                              └─> VSSMBlock(SS2D, FP32) ─ 上采样回 (H8p,W8p) ─[裁回 (H8,W8)]─> F'  (B,128,H8,W8)
F' ─ proj_out(1x1) ─> 加到 c8 / c16 / c32 三份 stage 特征上
concat[short_path, pooled, F', c8', c16', c32'] ─ cat(1x1,GN,ReLU) ─> ctx (B,128,H8,W8)
ctx ─ 上采样到 c4 实际尺寸 ─ + lateral4(c4) ─ smooth4(3x3,GN,ReLU) ─ out(1x1) ─> pix (B,256,H4,W4)
```

- **每张图只算一次**，六层 HED 查询共享同一份 `pix`（代码里 `pix` 在解码之前算好，
  `mask_head` 对各层调用时传的是同一个张量）。不给每个分支各建一个 MM。
- **MM 只在像素支路**，它的输出 `pix` 唯一的去处是 MaskHead（点积生成掩码）。
  代码里**没有** MM → HED 查询更新 或 MM → 评分头 的前向连接；
  评分头读的是 HED 解码器输出的、已融合图文信息的查询特征，与 `pix` 无前向关系。
- 反向传播未受限制：`pix` 既不 detach 也不包 `no_grad`，掩码损失可以经 MM 回传到
  `enc_maps`（encoder/融合）与 `c4`（Swin stage-0）。`tests/test_mm_score.py` 有一项静态检查
  断言该文件里不出现 `.detach()` / `no_grad`。
- GroundingDINO 的第 4 个特征层（1/64）仍然给原 transformer 用，encoder 布局未改。

## 3. RefScoreHead：结构、监督、选择逻辑

`rrs/ref_score_head.py`：

```python
Linear(hidden_dim, hidden_dim) → ReLU → Linear(hidden_dim, 1)   # 再 .squeeze(-1)
```

- 模型里只建**一个** `self.ref_score_head`，对六层分别调用（共享权重，不是六个评分器）。
- 输出**原始 logits**，头内不 sigmoid；损失用 `binary_cross_entropy_with_logits`，推理时才 sigmoid。
- 用 `.squeeze(-1)` 而不是无参数 `.squeeze()`，B=1 或 Q=1 时不会把 batch/查询维消掉。
- 评分**在剥离 DN 之后**计算：`model.py` 先按 `num_dn` 切出普通查询（`hs_hed = [h[:, num_dn:] ...]`），
  再调用评分头。DN 不进评分、不进评分损失、不进 top1 选择、不进掩码。

### 输出字段

| 字段 | 形状 | 使用位置 |
|---|---|---|
| `pred_ref_logits` | `[B,Q]` 最后层原始 logits | 最后层评分损失 |
| `aux_outputs[i]['pred_ref_logits']` | `[B,Q]` 第 i 层 | 第 i 层评分损失 |
| `hed_all_ref_logits` | `[L,B,Q]`，L 从实际层数读 | 推理选 `q*` |
| `hed_mask_embeds` / `hed_pix` | 保持原有约定 | 选中查询的掩码生成 |

`use_ref_score=False` 时这些键**根本不存在**（不是置 None）。

### 训练监督

```text
z_l = ref_score_head(hs_l)                 # [B,Q] logits
y_l = 0                                     # 全部初始化为负样本
y_l[b, matched_query_indices_l[b]] = 1      # 复用该层自己的 HungarianMatcher 结果
L_ref_l = sigmoid_focal_loss(z_l.float(), y_l)   # alpha=0.25, gamma=2, FP32
         .sum() / max(batch 内 GT 数, 1)
```

- 标签来自 **该层自己的匹配**：`SetCriterion._single` 里匹配器只调用一次，`loss_ref_score`
  直接用同一份 `indices`。**不**为评分损失再调一次匹配器（匹配代价含随机点采样，
  再调会得到第二套不一致的匹配），**不**把最后一层的标签复制给其他层，
  **不**用模型自己的最高分当标签。
- 归一化与其余损失一致：`max(sum(len(t["boxes"])), 1.0)`。
- 全 batch 无目标：标签全负，损失仍有定义且可反传，不制造正目标。
- `interm_outputs`（encoder 中间层）与 `dn_outputs` **不加**评分损失。
- 评分**不**进入 Hungarian 匹配代价（本轮不改匹配）。
- **不** detach 查询特征：评分损失可以更新 HED 查询。原 token 分类 / 框 / 掩码损失完全不变。

### 损失汇总

```text
新总损失 = 原分类/框/掩码/interm/可选DN 总损失
         + ref_score_loss_coef × Σ_l 评分损失_l
```

- loss key：最后一层 `loss_ref_score`，辅助层 `loss_ref_score_0` … `loss_ref_score_4`。
  现有后缀去除逻辑 `re.sub(r"_(\d+|interm)$", "", k)` 能正确映射到 `weight_dict["loss_ref_score"]`。
- **六层逐项加权求和，不取平均**；训练日志里记录的也是同一组值（最后一层无后缀那项）。
- `ref_score_loss_coef` 默认 **1.0，未调参**。
- 评分开关关闭时不产生任何 `loss_ref_score*` 键，总损失与原来一致。
- 评分开启但某层缺 `pred_ref_logits` → `ValueError`，不解释成"这一层不用训练"。

**"评分损失确实进入总损失"怎么验证**：`criterion` 内部的匹配代价与掩码损失都有随机点采样，
两次调用之间不固定随机数就无法解释差值。因此两处检查都**先保存再恢复同一份 RNG 状态**
（`smoke_mm_score.py` 恢复 CPU + 全部 CUDA 状态；`test_mm_score.py` 恢复 CPU 状态），
然后断言：

```text
total(coef=w) - total(coef=0) ≈ w × Σ_l 评分损失_l     (容差 max(1e-3, |expect|·1e-4, |total|·1e-6))
且 其余所有损失项逐项不变                                (RNG 恢复生效的旁证)
```

两项都纳入 PASS 判定，不满足即非零退出。这只改测试流程（保存/恢复 RNG），**没有改生产训练逻辑**。

### 推理选择

```text
s[b,q]      = mean_l( sigmoid(hed_all_ref_logits[l,b,q]) )    # L 从张量第 0 维读
q_star[b]   = argmax_q s[b,q]
```

然后取**同一个** `q_star[b]` 在各层的 mask embedding，与同一份 `pix` 点积，逐层
"恢复 padding 画布 → 裁 padding → 恢复原图 → sigmoid"，再平均概率、阈值 0.5。
顺序与 `hed_mask_mode='avg'/'last'` 的语义完全沿用原实现：
**不**改成"logit 平均后 sigmoid"，**不**先平均 mask embedding。

- 评分模式由 `postprocess_for_model` 从**模型实例**的 `use_ref_score` 读取，
  不靠输出里有没有 `pred_ref_logits` 猜，CLI 配置与模型不一致会报错而不是静默换规则。
- 新模式下 `scores` 返回的就是**实际用于选择的新分数**，并带 `score_type="ref_score"`；
  旧 token 均分作为 `token_scores` 一并返回，**仅作诊断**，不参与选择，也不乘任何融合权重。
- 缺 `hed_all_ref_logits` → `ValueError`，不静默退回旧分数。
- 同一查询索引跨层集成是**继承自现有 HED 的设计假设**，并不等于已经证明六层永远指向同一物体；
  本轮不新增跨分支候选聚类或匹配。
- HED 后处理仍然只支持 `mode="top1"`，未扩展多目标/无目标；推理只用图像尺寸等元信息，
  不读 GT 框或掩码。
- 训练仍保留全部普通查询与各层监督，没有提前 argmax 裁成 top1：
  `mask_aux_layers=True` 时六层各自对**全部** Q 个查询算掩码并参与匹配与监督。
  "先评分、后画掩码"只描述**推理**里选 `q*` 并生成最终结果的逻辑，不是训练时的行为。

## 4. 开关、配置与权重加载

### 四组对照

| 模型 | `use_mmscope` | `use_ref_score` | 配置 |
|---|---|---|---|
| 原 B0_HED | 关 | 关 | `configs/b0_hed_rislad.py`（未改动） |
| B0_HED + MM | 开 | 关 | `configs/b0_hed_mm_rislad.py` |
| B0_HED + Score | 关 | 开 | `configs/b0_hed_score_rislad.py` |
| B0_HED + MM + Score | 开 | 开 | `configs/b0_hed_mm_score_rislad.py` |

四个配置都 `exec` 继承 `configs/b0_hed_rislad.py`，数据、`short_side=800`、`max_size=1333`、
`batch_size=2`、`grad_accum=2`、`lr=1e-4`、`epochs=12`、`lr_drop=8` 完全相同，只差开关与
`output_dir`。**DN 四组都保持关闭**；要做 HED+DN 版本用 `--opts use_dn=True`，
对照时四组必须一致。两个开关互不绑定：只开 Score 时继续用原 FPN 像素特征；
只开 MM 时继续用原 token 分数选查询。

### 模式恢复

- 优先级：**命令行显式 `--opts` > checkpoint 的 `cfg` > 新训练配置**（沿用原规则）。
- `MODE_FLAGS = (use_hed, hed_mask_mode, use_dn, use_mmscope, use_ref_score)`，
  旧 checkpoint 缺字段按 `False` / `"avg"` 恢复，**不从文件名猜结构**。
- 嵌套块 `dn` 与 `mm` 走同一套 `_resolve_sub`，支持 `--opts mm.channels=96 dn.reinit_rate=0`；
  未知子项报错。
- `ref_score_loss_coef` 是训练超参，不是结构标志，**不从 checkpoint 恢复**，由当前配置决定。
- `use_ref_score=True` 且 `use_hed=False` → 报错（`resolve_model_mode`、
  `GroundingDINORefSeg.__init__`、`build_model` 三处都挡）。
- `model_variant` 会输出 `HED-structure/no-DN+MM+Score`、`HED+DN+MM+Score` 等名称，写进日志。

### `--resume` 与 `--init-from`（严格区分）

| 命令 | 用途 | 加载内容 | 结构由谁决定 |
|---|---|---|---|
| `--resume` | 同架构恢复训练 / eval-only | 模型 + 优化器 + 调度器 + epoch + best | checkpoint 的 `cfg` |
| `--init-from` | 用旧权重初始化新架构 | **只有模型权重** | **当前配置** |

- 两者**互斥**（同时给 → `sys.exit`）；`--init-from` 也**不能**与 `--eval-only` 同用
  （随机初始化的新头不能冒充完整模型评估）。
- `--init-from` 调用 `resolve_model_mode(cfg, None, opts)`——**不**把旧 checkpoint 的 `cfg`
  传进去，所以旧 checkpoint 缺少的新标志不会把 MM/Score 意外关掉。
- `rrs/model.py::init_model_weights` 的缺键白名单**按「源 checkpoint 的开关 × 目标模型的开关」
  逐模块判定**，不是对某个前缀无条件放行（第二轮修正点 6）：

| 模块 | 源关 / 目标开 | 源开 / 目标开 | 源开 / 目标关 |
|---|---|---|---|
| `ref_score_head.*` | 允许整体新建，报告在 `new` 里 | **必须完整匹配，缺任何一个键就报错**（权重损坏/不完整不能当成"正常新增"） | 丢弃并报告在 `dropped` 里 |
| `dn_generator.*` | 允许新建（沿用原 DN 约定） | 完整匹配，缺则新建（原 DN 约定） | 丢弃 |
| `pixel_decoder.*` | 类型不同 → **整条支路丢弃并新建** | 类型相同 → **必须完整匹配，缺键报错** | 类型不同 → 整条丢弃并新建 |

  - 像素支路永远是"整条保留"或"整条重建"二选一，**绝不**因为同属性名、同形状就部分复用。
  - 另有一致性检查：`cfg` 说 `use_ref_score=False` 但权重里带着 `ref_score_head.*` 的键时
    直接报错（checkpoint 自相矛盾），否则目标开启评分头时会把真权重误判成"整体新建"丢掉。
  - 其余任何差异（白名单外的缺键、多余键、同名形状不符）一律 `RuntimeError`。
  - 源开关取自 checkpoint 里的 `cfg`；`cfg` 缺字段时按 `False` 处理——那时的 checkpoint
    只可能是 FPN / 无评分头。
- `MaskHead` / `c4_norm` / `gd.*` 形状与语义未变，按常规加载保留旧权重——
  **但请注意：不能宣称新模型"严格加载了旧 FPN 解码器的全部权重"，像素支路是整体替换的。**
- 日志会打印 `kept_count` / `kept_groups`（按前缀计数）/ `new` / `dropped` /
  `pixel_decoder_replaced` / `source_flags` / `decisions`（每个模块的判定依据）。
- 这些规则由 `tools/check_strict_loading.py`（真 checkpoint，断言式）与
  `tests/test_mm_score.py::TestInitModelWeights`（桩模型）两边覆盖。
- `load_model_state`（`--resume` / eval-only / infer 用）**不**给 MM/Score 任何豁免：
  缺 `ref_score_head.*` 这类键会直接报错，必须走 `--init-from`。
- **已知限制（沿用 DN 时的同一问题）**：从旧 checkpoint 用 `--init-from` 开始训练是重新开始的；
  不能从 no-MM/no-Score 的 checkpoint 用 `--resume` 直接打开新模块（优化器参数组成员数不同，
  `optimizer.load_state_dict` 会报错）。这是设计上的区分，不是 bug。

### 优化器

MM 与评分头的参数都在 `model.named_parameters()` 里，名字既不含 `lr_backbone_names`
（`"gd.backbone.0"`）也不含 `freeze_keywords`（`"gd.bert"`），因此自动落入 `rest` 组，
与原 `pixel_decoder` / `mask_head` 同一学习率。**没有新增参数组，没有改动旧参数组。**
官方 `VSSM` 的特殊初始化（`dt_init` 的 `uniform_` + `inv_dt` bias、`A_log_init` 的 S4D 实数初始化、
`D_init`）在 `mmscope_core.py` 里原样保留，模型没有做全局 re-init 覆盖它们。
唯一未对齐的是 `_no_weight_decay` 标记（见差异 A6）。

## 5. 静态检查过的接入风险

| 风险 | 结论 |
|---|---|
| Pixel Unshuffle 整除 | `pixel_unshuffle(4)` 要求 1/8 的 H、W 被 4 整除。800×1333 → 1/8 约 100×167（167 % 4 = 3），**不满足**。只在新模块内部 replicate-pad 到 4 的倍数，扫描后上采样回 pad 尺寸再裁回原尺寸。推导：pad 后 `h`（4 的倍数）下 `conv(k=5,s=4,p=1)` 输出 `h/4`，`conv(k=3,s=2,p=1)` 输出 `h/2` 再 unshuffle(2) 得 `h/4`，`unshuffle(4)` 也得 `h/4` —— 三路一致，可以 concat（已逐项核对 h=4,8,12,16,20） |
| 非方形 / 不假定方形 | 所有对齐都用目标张量的实际 `size=`，没有用 `scale_factor` |
| 对外尺寸语义 | `pix` 的空间尺寸严格等于 `c4`（`F.interpolate(..., size=lateral4(c4).shape[-2:])`），padding 完全在模块内部，不改变 padding 画布 → 裁 padding → 原图 的恢复顺序 |
| batch=1 的全局池化归一化 | 官方 `image_pool` 在 1×1 特征上做 BN，`batch=1` 训练时会报错。默认改用 GroupNorm（见 A2），改动只限新支路，有配置项 `mm.norm` 且已记录 |
| AMP / dtype / 连续内存 | `selective_scan_cuda_oflex.cpp` 要求 `delta/B/C` 与 `u` 同 dtype、`A/D/delta_bias` 为 `float`、最后一维 stride=1（已读 `TORCH_CHECK`）。`mm.scan_fp32=True` 只在扫描处转 FP32；官方 `VSSM.forward` 内部的 `.contiguous()` 保持原样。`A_logs`/`Ds`/`dt_projs_bias` 本就按官方 `.to(torch.float)` |
| 梯度 | 新支路不 detach、不 `no_grad`（有静态断言）。实际梯度有效性由服务器验证，验收口径见下 |
| 既有修复保留 | 参考框梯度修复（`head_refs`）、DN 分离（评分在 split 之后）、训练用原始 logits、空间恢复顺序，全部未改 |

### 5.1 梯度验收的口径（第二轮修正点 4）

`smoke_mm_score.py` 在 `scaler.unscale_(optimizer)` 之后、`step` 之前逐参数分类，
**不是**只统计"有几个非零梯度然后判断大于零"（那样一个参数正常就能掩盖同模块其他参数的 NaN）：

| 分类 | 含义 | 是否判失败 |
|---|---|---|
| `with_grad` | 梯度有限且非零（计数） | — |
| `none_frozen` | `.grad is None` 且 `requires_grad=False`（如冻结的 `gd.bert`） | **不**失败，这是预期 |
| `none_unused` | `.grad is None` 但可训练——本次没参与反传 | 一般只记录；**新增模块（评分头、SS2D 核心）出现即失败** |
| `all_zero` | 梯度有限但全零 | **不**失败（单 batch 下某些参数本就可能零梯度） |
| `nonfinite` | 出现 NaN / Inf | **任何应参与训练的参数出现即失败** |

另外：某个模块**完全没有**参数拿到有效梯度（疑似断路）→ 失败。

参数更新检查覆盖**全部五个官方 SS2D 参数**（`A_logs` / `Ds` / `x_proj_weight` /
`dt_projs_weight` / `dt_projs_bias`）加上 `linear_fuse` / `out`，以及评分头的两层权重——
只看像素支路第一个投影层不算。还会核对这些参数确实在 `optimizer.param_groups` 里，
并记录每个观察点的 `|Δ|` 最大值；被 `GradScaler` 因非有限梯度**跳过**的 `step` 判为失败。
这套分类逻辑本身由 `test_mm_score.py::TestGradReportLogic` 用造出的 NaN / None / 全零
场景覆盖（含"一个参数正常、另一个 NaN 时必须失败"的回归用例）。
| 输出字段 / loss key / 构建参数 / 保存恢复 | 逐项对应，见第 3、4 节 |
| 评分启用却缺字段 | `criterion`（`ValueError`）与 `postprocess_hed`（`ValueError`）两处都报错，不静默退回旧分数 |

### 6.2 一键验收

```bash
bash scripts/verify_mm_score.sh
# 有旧 HED 权重时指定它, 以便跑 --init-from / --resume / eval-only / infer:
OLD_CKPT=work_dirs/b0_hed_rislad_noDN/best.pth bash scripts/verify_mm_score.sh

**判定方式**：每一项记录 `PASS` / `FAIL` / `SKIP` 与真实退出码。

`SKIP` 只用于前置条件缺失（例如没有旧 checkpoint），summary 会写明如何补齐——
**SKIP 绝不等于通过**，未执行的 `--resume` / `eval-only` / `infer` 会明确标为 SKIP。

**输出**：每次运行一个独立目录 `work_dirs/verify_mm_<时间戳>/`，
里面有 `summary.txt`（汇总表，把这个发回即可）和每项的完整 `.log`（不截断，

真实 SS2D 算子前后向（`check_ss2d.py`）、`test_mm_score.py` 的控制流测试、

python tools/smoke_dn.py --config configs/b0_hed_dn_rislad.py --iters 2    # 原 DN 短测试

# 严格加载规则 (需要一个本项目的 checkpoint)
python tools/check_strict_loading.py --ckpt work_dirs/<某次>/last.pth
```

`smoke_mm_score.py` 的训练路径与 `tools/train.py` 一致：同样的 `GradScaler` 构造
（含 torch<2.3 的兼容分支）、`scaler.scale(loss/grad_accum).backward()` →
`scaler.unscale_(optimizer)` → `clip_grad_norm_` → `scaler.step/update`。
梯度检查在 `unscale_` 之后、`step` 之前做（此时 `.grad` 是真实量级）。
AMP 关闭时走同一条代码路径（`GradScaler(enabled=False)` 的 `unscale_`/`update` 是空操作，
`step` 直接转发给 `optimizer.step`）。
短测试会把 `grad_accum` 压到 `min(cfg.grad_accum, iters)` 并把实际值记进报告，
以保证本次测试内**至少完成一次真实的 `optimizer.step`**——否则"参数已更新"无从谈起；
正式训练仍用配置里的 `grad_accum`，生产逻辑未改。
报告里记录 scaler 的 scale 变化，**因梯度非有限被 scaler 跳过的 step 判为失败**，不算成功更新。

### 6.3.1 PASS / FAIL / SKIP 的判断方法

| 层级 | 怎么判断 |
|---|---|
| 单个 Python 脚本 | 每个脚本内部累计 `ok`，最后 `sys.exit(0 if ok else 1)`，并把判定依据写进 JSON（`work_dirs/*.json`）。`unittest` 脚本用自身的退出码。**不存在"只打印 FAILED 然后正常结束"的分支。** |
| `setup_mmscope.sh` | 依赖自检在子 Python 里收集失败列表，`sys.exit(1)`；外层捕获该退出码，非零时打印按版本处理的建议并**以同一退出码结束**。 |
| `verify_mm_score.sh` | 每项用 `run`（命令完整输出重定向到独立 `.log`，`$?` 即该命令自己的退出码，不经管道，因此不依赖 `PIPESTATUS`）记录 `PASS`/`FAIL`；前置条件缺失的项用 `skip` 记录 `SKIP`。失败不中断，继续收集；**最后 `FAILED != 0` 就 `exit 1`**。日志写入失败（`tee` 报错）会立即退出。 |
| `SKIP` 的含义 | 仅表示"该项**未执行**"，summary 里同时给出补齐方式。**SKIP 不计入通过**，也不会被描述成已验证。 |
| 残留文件干扰 | 每次运行写入 `work_dirs/verify_mm_<时间戳>/`，`--init-from` 产物在该目录的 `tmp_initfrom/`。5b–5e 只认 5a 本次生成的 `last.pth`：若 5a 失败，这几项变成 `SKIP` 而不是去读历史残留文件。 |

## 8. 本次迁移的性质，以及未验证事项

### 8.1 怎样描述这次迁移才准确

- 可以说的：**基于固定版本（commit `9ced66ab`）的 SegMAN 源码迁移，并做了接口适配**。
  其中 `VSSM`(SS2D) / `VSSMBlock` / `FFN` / `SelectiveScanOflex` / `LayerNorm2d` / `LayerScale`
  这 6 个计算单元的源码文本已与官方逐字符比对一致（L0，见下表）；
  `forward_mlp_decoder` / `forward_winssm` 是按原语句顺序改写、可逐行比对的（**未做字符级比对**，
  因为输入层级与 pad/FP32 适配本就不同）。
- **不能**说的：已证明与官方实现等价。源码文本一致 ≠ 运行时数值等价，本项目没有做过后者的证明。
- 验证被拆成两层，不要混在一起谈：

| 层次 | 内容 | 状态 |
|---|---|---|
| L0 源码文本一致性 | 抽取的 6 个类去注释与空白后与官方逐字符比对 | **已在本机用 shell 文本工具完成**（未运行 Python），逐类字符数见 [`VERSION.md`](../third_party/SegMAN/VERSION.md)。这只证明源码文本一致，不证明数值等价 |
| L1 真实 SS2D 核心 | 同权重前后向、确定性、与官方 `forward` 语句顺序的分步重算对照、dtype、非整除尺寸 | 已写成 `tools/check_ss2d.py`，**待服务器执行** |
| L2 适配后的完整像素支路 | `MMSCopEPixelDecoder` 的几何、梯度连通、与 MaskHead 的接线 | 几何/接线在 `test_mm_score.py`（SS2D 用卷积桩），真实算子版在 `smoke_mm_score.py`，**待服务器执行** |
| L3 与官方完整 `SegMANDecoder` 逐元素相等 | — | **未实现，也不打算声称成立**：GroupNorm 替换 SyncBN、输入层级与通道都不同，逐元素相等不成立。这不是"核心计算无法验证"的理由——核心计算由 L1 覆盖。 |

- 单元测试里的卷积桩只验证接口与几何，**不是**真实 CUDA 扫描的验证；
  真实算子的验证独立标在 `check_ss2d.py` 与 `smoke_mm_score.py`。

### 8.2 结构描述的准确说法

- MM 位于**像素支路**，为 MaskHead 提供多尺度上下文特征。
  代码里**没有** MM 输出 → HED 查询 或 MM 输出 → 评分头 的前向连接。
- RefScoreHead 读的是**已融合图文信息的 HED 查询特征**，与 MM 的输出无前向连接。
- 训练时**仍然**为各层普通查询生成用于匹配和监督的候选掩码（`mask_aux_layers=True`）。
  "先评分、后画掩码"是**推理**中选择 `q*` 并生成最终结果的解释，
  **不代表**训练时只算被选中的那一个掩码。
- RefScoreHead 是一个普通的两层 MLP + focal 监督，是**本项目的起步设计**，
  不宣称它本身是已成立的论文创新。

### 8.3 未验证事项

1. **本机未运行任何测试。** 没有安装依赖、没有编译 CUDA、没有导入模型、没有跑
   `py_compile` / 单元测试 / 前向 / 反向 / 推理 / 训练。以上所有命令与结果都待服务器验证。
2. `selective_scan_cuda_oflex` 与 triton 在服务器的 **torch 2.8.0+cu128 / CUDA 12.8** 上
   能否正确编译并给出正确结果未验证（官方声明 2.1.2）。此前编译失败的根因尚需完整日志确认。
   `setup_mmscope.sh` 已修复架构设置不生效的问题，并保留独立编译日志；
   **改完之后没有在本机执行编译或运行测试**。
   timm 的 `DropPath` 导入路径已做兼容但未实测。
3. MM 的显存与速度未实测。扫描在 1/32 分辨率且 FP32，加上 1/8 上的若干卷积，
   `batch_size=2` / 800×1333 下的峰值显存与每轮耗时都需要 `smoke_mm_score.py` 的实测数据。
4. L3（与官方完整解码器逐元素对照）未实现，见 8.1。L1 的同权重前后向对照已写好但未执行。
5. autocast(fp16) 下直接调用官方 `VSSM` 会不会因 dtype 校验失败，**尚未实测**；
   `check_ss2d.py` 会把实测结果记进报告。项目实际走的是 `mm.scan_fp32=True`（扫描处转 FP32）。
6. 评分头是否真的提升选对率、MM 是否真的改善分割——**完全未知**，需要四组对照的正式训练。
   `ref_score_loss_coef=1.0` 与 `mm.channels=128` 都没有调参。**不保证指标提升。**
7. 多目标 / 空目标 batch 的真实数据训练数值未测（与 DN 阶段相同的缺口）。
   HED 的 top1 推理**不**支持无目标识别，这一点没有改变。
8. `build_optimizer` 未按官方 `_no_weight_decay` 标记排除 `A_logs` / `Ds` 的 weight decay
   （见差异 A6），与官方 MMSeg 配置不同；其影响未评估。
9. 小样本过拟合与四组 12 轮正式对照训练都未执行，由你决定何时跑。
